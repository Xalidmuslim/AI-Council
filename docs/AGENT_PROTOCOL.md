# Протокол трёх агентов — AI-Council

Версия: 2026-11-14. Это **инструкции и профили**, а не уже запущенные автономные процессы. Они действуют только когда ChatGPT Work/Codex/совместимый агент действительно получил этот файл и доступ к целевому репозиторию.

## Роли и последовательность
- **Программист** — RECON → тест-воспроизведение → минимальный diff → PR → передача тестировщику.
- **Арабист** — проверка первоисточника и Unicode/огласовок → список обоснованных замен → передача программисту (если код должен измениться) и тестировщику.
- **Тестировщик** — независимый контроль diff/контента/CI → VERIFIED, FAILED или NEEDS_CHECK. Не выдаёт отсутствие проверки за успех.
- **Координатор (Work)** — получает задачу, выбирает роль, не объявляет о параллельной работе без фактического запуска, консолидирует результаты и запрашивает согласие на merge.

## Контракт задания (вход)
```yaml
task_id: # GitHub issue URL или явный идентификатор
repository: # owner/repo; убедиться, что доступ реально есть
base_ref: # ветка или commit; не угадывать
role: programmer | arabist | tester
objective: # одна проверяемая цель
scope: # разрешённые файлы/экраны/главы
source_refs: # для текстов первоисточники, страницы, варианты
acceptance: # конкретные критерии приёмки
constraints: # сохранение пользовательских данных, RTL и т. д.
```

## Контракт результата (выход)
```yaml
status: VERIFIED | FAILED | NEEDS_CHECK
repository:
base_commit:
result_commit:
changes: # список файлов или «нет изменений»
evidence: # пути, номера страниц, ссылки на CI, логи
tests_run: # реальные команды, exit code, CI URL; либо «не запускались»
limitations: # отсутствующий доступ, устройство, исходник
risks: # сохраняющиеся проблемы
next_action: # кто и что проверяет дальше
```

## Правила безопасности
- На первом этапе **только отдельные ветки и draft PR**. Основная ветка, релизы, secrets, платежи и пользовательские данные остаются без изменений.
- Ни один агент не может подменять «проверено» на «предположительно». Результаты со статусом NEEDS_CHECK передаются человеку.
- Запрещено фабриковать цитаты, арабские первоисточники, результаты тестирования и APK.
- Книжные тексты, аяты, хадисы, переводы и огласовки не заменять массово без проверенного источника, отчёта по каждой правке и отдельного одобрения.
- Для добавления команды в Work пользователь должен указать репозиторий/ветку и попросить прочесть данный протокол; одни файлы на GitHub **не активируют** ChatGPT Work.

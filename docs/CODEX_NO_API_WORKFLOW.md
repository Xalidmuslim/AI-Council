# AI-Council без отдельного OpenAI API: Codex Cloud + GitHub Actions

**Состояние: 18 ноября 2026.** Это ручной, но воспроизводимый маршрут от Issue к проверенному черновому PR. Он не является автоматически запущенной многомодельной системой. Авторизация Codex Cloud и две отдельные задачи выполняются в аккаунте владельца.

## Почему это работает без отдельного API

- Codex Cloud может использовать доступ через аккаунт ChatGPT в пределах лимитов тарифа. Нет необходимости создавать `OPENAI_API_KEY` или оплачивать Responses API по счётчику для этого сценария.
- Код и рабочие ветки обрабатываются в авторизованной среде Codex, а не внутри публичного репозитория AI-Council.
- GitHub Actions выполняет детерминированные тесты Flutter/Python, не вызывая никаких LLM.
- Проверяющий — отдельная задача Codex с новым контекстом, запускаемая владельцем вручную. До её запуска **нет** независимого агента-проверяющего.
- Постоянный автономный цикл «Issue → сразу Codex → PR → Codex review» из одного коммита AGENTS.md не появляется. Без специальных возможностей продукта или внешнего исполнителя автоматическая передача между задачами не настроена.

## Подготовка без сети и без AI-запросов

```bash
python3 tools/codex_handoff.py \
  --task agent_inputs/codex_cloud_pilot_48.json \
  --out handoff_reports/codex
```

Команда проверяет поля, публичный репозиторий, URL Issue, полный immutable SHA, scope и только безопасные команды тестов. Результат:
- `handoff_reports/codex/handoff.json` — исходный контракт и статус NEEDS_CHECK;
- `handoff_reports/codex/programmer.md` — инструкция для первого запуска Codex;
- `handoff_reports/codex/reviewer.md` — отдельная инструкция проверяющего.

Также `.github/workflows/codex-no-api-handoff.yml` генерирует тот же artifact через GitHub Actions. В этом workflow права только `contents: read`, нет секретов, OPENAI API или PR merge.

## Подключение в ChatGPT / Codex Cloud

1. На веб-сайте [Codex](https://chatgpt.com/codex) войти своим аккаунтом ChatGPT и открыть Codex Cloud.
2. Создать/настроить облачную среду для `Xalidmuslim/Arabic-Academy-Flutter`; установить GitHub-подключение и выбрать конкретный репозиторий. По официальной документации создание/публикация сред выполняется на **вебе или десктопе**, после чего задачи доступны также с Android.
3. Убедиться, что Codex реально открывает исходники и имеет нужный доступ к веткам. Подключение обычного GitHub-плагина к чату **не** заменяет настройку Codex.
4. Открыть **новую** задачу Codex на Flutter-репозитории и передать полный текст `programmer.md`. Перед редактированием Codex обязан читать локальный `AGENTS.md`, проверить текущую ветку, последний commit, и сопоставить baseline с текущим кодом. Если baseline устарел, остановиться и согласовать новый SHA; не откатывать уже выполненные изменения.
5. После завершения изучить созданный **draft PR**. Если Codex не смог открыть ветку/PR, принять patch отдельно, но не объявлять работу слитой. Подтвердить реальные тесты и ссылку GitHub Actions.
6. Создать **вторую, отдельную** задачу Codex для проверки, передать `reviewer.md`, ссылку на фактический draft PR и SHA его HEAD. Проверяющий читает полный diff, тесты и логи, не ссылаясь на слова программиста как на факт.
7. Исправить найденное в отдельном цикле, повторить тесты. Merge — только после твоего осознанного решения.

## Риски и меры

- **Лимиты:** Codex в составе ChatGPT не означает безлимит; не делать выводов о конкретном тарифе или доступности среды без проверки аккаунта.
- **Границы:** публичный AI-Council содержит только публичный контракт и статусы; закрытые Kotlin/Flutter-проекты нельзя копировать в публичные logs/artifacts.
- **Evidence:** `flutter analyze` может выводить `info` о deprecation — они остаются видимыми. `--no-fatal-infos` не маскирует warning/error. Фактический CI результат важнее заявления модели.
- **Грамматика:** для арабистики нужно отдельно сверять арабские первоисточники и огласовки, не подменять сверку Unicode-тестами.
- **Среда:** GitHub workflow может пройти и без выполнения Codex задачи. Это означает только успешное создание handoff, а не работу агента.
- **Существующие изменения:** PR №6–10 остаются отдельными незавершёнными экспериментами. Особенно API-only PR №10 и старый `cloud-agent.yml` не нужно активировать для этого маршрута. Настройки `AI_CODING_ENABLED`, `AI_AUTOMATION_ENABLED` оставлять выключенными.

## Как масштабировать

После реального пилота Issue #48 добавить аналогичные локальные `AGENTS.md`, PR-CI и ограниченные issue-контракты для конкретных **частных** Android-репозиториев внутри их собственных защищённых Codex сред. Не объединять разнородные стеки или разные репозитории в одном общем публичном runtime.

**Готовность определяется:** реальный Codex Cloud run → зафиксированный PR и commit → зелёный CI → отдельный reviewer run → решение владельца. Без этих пяти пунктов статус остаётся `NEEDS_CHECK`.

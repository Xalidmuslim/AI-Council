# AI-Council — безопасный приём внешнего публичного репозитория

Версия: 2026-11-18. Реализован **read-only intake** (метаданные и план передачи задач), а **не** автономный программист.

## Возможности
- Только вручную: GitHub Actions → `AI-Council public repository intake (read only)` → Run workflow.
- На первом этапе разрешён только `Xalidmuslim/Arabic-Academy-Flutter`. Имя проверяется дважды: allowlist в Python и обязательный public статус из GitHub API.
- Требуется явный `ref` (ветка или тег), который разрешается в полный commit SHA. Дальнейшая проверка дерева привязана к SHA.
- Обнаруживает Flutter/Android/неизвестный стек, инструкции AGENTS.md, тестовые файлы, CI-workflows и кандидатов на контент.
- Создаёт `repository-intake.json` и `repository-intake.md` как GitHub Actions artifact сроком 7 дней.
- Формирует задачи по ролям programmer → arabist → tester, но **не запускает эти модели**.
- Сохраняет `NEEDS_CHECK`: ни одно найденное имя теста не считается выполненным тестом.

## Запуск
1. После ревью и отдельного утверждения PR с данным workflow он должен оказаться в `main`: GitHub workflow_dispatch запускается только тогда, когда workflow присутствует в основной ветке.
2. В AI-Council открой Actions → AI-Council public repository intake (read only) → Run workflow.
3. Выбери `Xalidmuslim/Arabic-Academy-Flutter` и конкретную ветку, например `main`.
4. Скачай artifact `public-repository-intake`; там структурированный JSON и читаемый Markdown.
5. Передай отчёт агенту в Work/Codex, у которого **отдельно предоставлен доступ** к целевому репозиторию и к его `AGENTS.md`. Проверь scope, реальную ветку, файл и тесты до редактирования. Ничего не сливать автоматически.

Локально:
```bash
python3 tools/repository_intake.py \
  --repository Xalidmuslim/Arabic-Academy-Flutter \
  --ref main \
  --output-prefix intake_reports/repository-intake
```

## Почему не приватный Malina-PRO-Android
AI-Council — **публичный** репозиторий. Содержимое GitHub Actions logs и artifacts потенциально доступно посторонним, поэтому не добавлять private-репозитории в allowlist. Даже если API-token имеет права читать приватный проект, код отклоняет `private=true` и непрозрачную видимость.

Для приватных исходников использовать приватную отдельную среду Work/Codex с авторизованным GitHub-коннектором либо отдельный закрытый репозиторий-исполнитель с проверенными правами и настройками доступа. **Не добавлять персональные access tokens или приватный код сюда.**

## Реальные границы
- В этом workflow **нет OpenAI API**, `OPENAI_API_KEY` и расходов на модель.
- Не запускает Gradle, Flutter, тесты на устройстве, сборку APK или измерения FPS.
- Не создаёт Pull Request в целевом репозитории, не сливает ветки.
- Список файлов — только метаданные GitHub; содержимое не читается.
- Три роли — структура передачи задач; независимость/параллельность появится лишь после подключения и реального запуска исполнителей.
- Для арабских текстов первоисточники и сверка огласовок нужны отдельно.
- GitHub API может ограничивать выдачу большого дерева; если дерево обрезано, инструмент завершает работу с ошибкой вместо неполного отчёта.

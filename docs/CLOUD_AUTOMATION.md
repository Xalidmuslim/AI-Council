# Безопасный облачный ИИ-агент — пилот

### Что подготовлено
GitHub Actions может каждый день в 04:23 UTC проверить очередь задач. По умолчанию AI_AUTOMATION_ENABLED отсутствует, поэтому платные вызовы ИИ не выполняются. После явного включения и настройки OPENAI_API_KEY один запуск обрабатывает не больше одного Issue, созданного владельцем репозитория. Для каждой задачи выполняются два обращения к OpenAI Responses API: арабист + независимый проверяющий или программист-аудитор + тестировщик.

Результат сохраняется как GitHub Actions artifact cloud-agent-review на 14 дней. Issue переводится из [AGENT:pending] в [AGENT:review]. Никаких автоматических изменений кода, коммитов, слияния веток, публикаций или APK. Итоговый статус NEEDS_CHECK, пока человек не утвердит результат.

### Включение на телефоне
1. После ревью принять PR №3 в AI-Council. Запуск по расписанию работает только из основной ветки.
2. GitHub → Xalidmuslim/AI-Council → Settings → Secrets and variables → Actions → Repository secrets: добавить OPENAI_API_KEY. Не публиковать его и не отправлять в чат.
3. Там же в Variables добавить OPENAI_MODEL — название доступной модели, и AI_AUTOMATION_ENABLED = true — только после настройки финансового лимита у API-провайдера.
4. Создать в AI-Council Issue с заголовком [AGENT:pending] Пилот арабского перевода и телом (строго JSON, без Markdown):
{"role":"arabist","source_path":"agent_inputs/sample_arabic.txt","objective":"Сверь арабскую фразу, выполни литературный перевод и отдельно отметь сомнения."}
5. Открыть Actions → AI cloud agent (review only) → Run workflow либо оставить ежедневную проверку очереди.
6. Смотреть отчёт в artifact workflow run. В GitHub Issue будет комментарий и статус [AGENT:review].

### Защита и ограничения
Репозиторий AI-Council публичный. НЕ помещать сюда конфиденциальные книги, неопубликованные переводы, личную переписку или секреты. В пилоте исходник читается только из папок agent_inputs, docs, tools, tests этого репозитория (UTF-8, не больше 12000 символов). Запрещены относительные пути наружу и чтение остальных файлов. Открывать задачи может только владелец репозитория, сторонние Issue игнорируются.

Лимит: максимум одна задача и два вызова модели за запуск, до 1600 выходных токенов на вызов. Это ограничивает размер операции, но НЕ устанавливает финансовый потолок: настройте отдельные лимиты в API-аккаунте. ChatGPT Plus не оплачивает API. При ошибке после первого вызова повторный запуск может повторить расходы. Включение требует API-ключа; без него работа не начинается.

Это первая версия исполнительного механизма, а не работающая безусловно команда самостоятельных разработчиков. Для проверенной арабской литературы нужны первоисточники и человеческое утверждение. Для Android/Flutter программирования — отдельный запуск Codex, реальный репозиторий и реальные тесты. Генерация изображений пока не подключена.

### Надёжность очереди и ручное восстановление
Переходы состояний Issue: `[AGENT:pending]` → `[AGENT:running]` → `[AGENT:review]`. Сначала исполнитель пытается пометить Issue как running, и только после успешного ответа GitHub обращается к платной модели. При недоступном GitHub API вызова модели не будет. Если запрос к модели оборвался либо публикация отчёта завершилась ошибкой, Issue остаётся running и не попадёт в очередь повторно автоматически. Это уменьшает риск непреднамеренных повторных расходов, **но не гарантирует exactly-once**, поскольку изменение заголовка Issue не является атомарной блокировкой в распределённой системе.

Для восстановления: проверь GitHub Actions run и usage в API, затем вручную верни `[AGENT:pending]` только если осознанно допускаешь повторный расход, или зафиксируй отчёт вручную и переведи задачу в `[AGENT:review]`. Не переводить `[AGENT:running]` обратно автоматически.

### Разные модели исполнителя и проверяющего
Необязательная GitHub Actions variable `OPENAI_REVIEW_MODEL` задаёт **API-идентификатор модели для второго шага** (tester). `OPENAI_MODEL` остаётся моделью первого шага (arabist/programmer). Если `OPENAI_REVIEW_MODEL` не задана, оба запроса используют `OPENAI_MODEL`. В обоих случаях это два независимых по входам API-запроса, а не доказательство разных поставщиков, и оба могут ошибаться одинаково.

Использовать только идентификаторы моделей, доступные в своём API-аккаунте; название модели в меню ChatGPT не обязательно совпадает с API-именем. Платные вызовы по-прежнему выключены до `AI_AUTOMATION_ENABLED=true`. Не подключается кодирование, публикация PR или автоматический merge.

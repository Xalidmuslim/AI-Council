# Reference-to-Android: строгая визуальная проверка

`tools/reference_qa.py` дополняет уже имеющийся `.agents/skills/replica-diff/imgdiff.py`.
Он **не** заменяет размеры, не обрезает скриншоты, не векторизует графику, не меняет исходные изображения.
В отличие от режима `layout` в старом скрипте, проверяет каждый пиксель в полном разрешении.

## Статус и ограничения

- Нужны **два PNG одного разрешения и состояния**: утверждённый референс и скриншот установленного Android-приложения.
- Цвета сравниваются по значениям каналов RGB после композиции прозрачности на выбранном фоне (`#FFFFFF` по умолчанию). Это не аппаратная калибровка дисплея и не учёт ICC профилей.
- Ожидаются одинаковые размер экрана, плотность интерфейса, системные панели, шрифты, текущее содержимое и язык. **Растягивания и подгонки референса не будет.**
- Масками исключайте только действительно динамические области (часы, случайные аватары). Маска ограничена 20% экрана, а без неё проверяется всё.
- Порог по умолчанию: отклонение канала более 2 из 255, разрешено не более 0.5% изменённых пикселей. Это не гарантия «100% совпадения» на всех устройствах.
- `diff.png` подсвечивает несовпадающие пиксели красным, `overlay.png` накладывает изображения друг на друга, `report.json` содержит метрики.

## Локальный запуск

```bash
python3 -m pip install -r requirements-visual-qa.txt
python3 tools/reference_qa.py reference/home.png actual/home.png \
  --out-dir visual-qa-report --tolerance 2 --max-changed-percent 0.5
```

Коды возврата: `0` — в рамках порога, `1` — слишком много отличий, `2` — файл отсутствует, размер не совпадает или некорректные настройки. Даже при ошибке геометрии сохраняется JSON с размерами.

## Снимок с Android (если доступен ADB)

```bash
adb exec-out screencap -p > actual/home.png
```

Снимок следует делать с **реально установленного приложения** после открытия нужного экрана. Не считать `adb` доступным без проверки Android SDK/устройства.

## Исключение динамической области

Пример `mask.json`:

```json
{"ignore_regions": [{"x": 0, "y": 0, "width": 120, "height": 35}]}
```

Затем добавьте `--mask mask.json`. При работе без маски контроль строже.

## GitHub Actions

Workflow `.github/workflows/reference-qa.yml` запускается **вручную**, чтобы не расходовать лимит GitHub Actions на каждом коммите. Он также поддерживает `workflow_call` для других репозиториев. Прежде чем запускать, разместите в вызывающем репозитории два реальных PNG, например `visual-qa/reference/home.png` и `visual-qa/actual/home.png`. **Workflow не генерирует снимок Android сам по себе**: это отдельный этап с устройством/эмулятором.

Для другого репозитория создайте workflow, который вызывает:

```yaml
jobs:
  compare:
    uses: Xalidmuslim/AI-Council/.github/workflows/reference-qa.yml@main
    with:
      reference: visual-qa/reference/home.png
      actual: visual-qa/actual/home.png
```

В завершении запуска появится отчёт и архив `Reference-QA-report` с diff/overlay/JSON. Если исходников или референса нет — проверка не может считаться пройденной.

## Что дальше

Для настоящей сквозной проверки понадобятся эталонные референсы и экранные скриншоты целевого приложения. Для приложения «Баяна Ядейк» сначала подтвердить **актуальный GitHub-репозиторий и ветку**, прежде чем внедрять capture и менять код. Для нативного Android не переписывать код под веб; сборку APK и FPS проверять отдельно.
